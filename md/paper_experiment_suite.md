# Paper experiment suite (RQ1/RQ2/RQ3)

This file documents the paper-facing experiment tasks added around the frozen
`ren_balanced` recipe.  The scientific default remains unchanged:

- `g=[KL(T||C)-KL(T||H)]_+`, `w=g/(1+g)`;
- reasoning-token -> rollout -> prompt reduction, no weight renormalization;
- 8192-token on-policy rollout, four optimizer updates, matched causal/live path;
- control coefficient 0.5, reference coefficient 0.1;
- sampled 32768-token evaluation with response text and token IDs retained.

The new task code changes *controls, telemetry, and orchestration*; it does not
change the completed 2026-09-18 positive ReN snapshot.

## RQ1: matched baselines

```bash
SOURCE_EXPERIMENT=/.../ren_balanced_matched_b256... \
OUTPUT_DIR=/.../rq1_baselines \
bash Lulu/runs/run_rq1_baselines.sh
```

`run_rq1_baselines.py` runs, from the same source recipe:

- Control/Reference only (`reasoning_ablation=none`);
- Vanilla OPD (`w=1` on reasoning positions);
- matched direct-hindsight OPSD (`p_H` is the reasoning/control target).

The already-completed source ReN Round4 checkpoint and a fresh Base are included
in the same evaluation job.  `summarize_rq1_baselines.py` writes
`analysis/main_results.csv` with raw benchmarks plus Math Avg., OOD Avg.,
external macro/micro and deltas from the fresh Base.

The runner is source-experiment driven, so the same baseline controller can be
used for Qwen3-1.7B, Qwen3-4B, or a future cross-family ReN source recipe as long
as that source recipe passes the project's tokenizer/reasoning-region checks.

## RQ2.1/RQ2.2: matched supervision-allocation controls

```bash
SOURCE_EXPERIMENT=/.../ren_balanced_matched_b256... \
OUTPUT_DIR=/.../rq2_allocation \
bash Lulu/runs/run_rq2_allocation.sh
```

The controller runs:

- **Uniform-Matched**: same per-rollout ReN weight mass spread uniformly across
  that rollout's reasoning positions;
- **Shuffled-ReN**: the exact within-rollout ReN weight multiset is preserved,
  but deterministically permuted across positions;
- **Causal-Matched**: the exact weight multiset is preserved, but assigned by
  causal `D_C=KL(T||C)` rank only.

These are on-policy controls: every arm uses the same prompt schedule, budgets,
sampling recipe and optimizer recipe, but after an arm updates its own future
rollouts are necessarily generated by that arm's current Student.

`analyze_rq2_geometry.py` extracts the RQ2.2 metric relationship from the source
ReN diagnostics.  It uses equal trajectory weighting, scopes trajectory IDs by
round, and writes:

- `dc_delta_quantiles.csv`: conditional `D_C` / `D_C-D_H` quantiles;
- `topk_overlap.csv`: ReN-vs-causal top-k ranking overlap and a random-overlap
  reference;
- `summary.json`.

`summarize_rq2_allocation.py` writes `analysis/performance.csv` and
`analysis/allocation_dynamics.csv`, including both token-global and the actual
prompt-balanced Teacher-KL retention ratios.

## RQ2.3: Teacher-strength sweep

```bash
SOURCE_EXPERIMENT=/.../ren_balanced_matched_b256... \
OUTPUT_DIR=/.../rq2_teacher_sweep \
TEACHER_4B=/models/Qwen3-4B \
TEACHER_8B=/models/Qwen3-8B \
TEACHER_14B=/models/Qwen3-14B \
TEACHER_32B=/models/Qwen3-32B \
bash Lulu/runs/run_rq2_teacher_sweep.sh
```

The paper wrapper runs matched **Vanilla + ReN** for every Teacher and also runs
standalone Teacher evaluation, so the x-axis can use measured Teacher capability
rather than parameter count.  Student rounds 1--4 are retained.

`summarize_rq2_teacher_sweep.py` writes:

- `analysis/performance.csv`: Student performance, deltas, Teacher Math Avg. and
  measured Teacher--Student Math gap when Teacher evaluation is available;
- `analysis/teacher_capability.csv`;
- `analysis/round_dynamics.csv`: `D_C`, signed resolution, positive fraction,
  mean ReN/applied weights, top-1/top-10 concentration, prompt ESS, both
  Teacher-KL retention definitions, score tokens/positions, service time and
  round time;
- `analysis/resolved_distribution_quantiles.csv`: p01--p99 signed
  `D_C-D_H` quantiles for every Teacher/method/round.

For the fixed-prefix policy-drift panel, after the sweep completes:

```bash
EXPERIMENT_DIR=/.../rq2_teacher_sweep GPU=0 \
bash Lulu/runs/run_rq2_policy_drift.sh
```

This reuses one frozen round-0 Student rollout set and teacher-forces every
retained Student checkpoint on the same positions.  It generates no new text
and writes `analysis/policy_drift/policy_drift.csv` with forward/reverse KL and
TV from the common Base policy.

## RQ3.1: on-policy supervision scaling

Default paper budgets keep four optimizer updates fixed and vary fresh prompt
coverage:

| prompts / round | rounds | unique prompts |
|---:|---:|---:|
| 64 | 4 | 256 |
| 128 | 4 | 512 |
| 256 | 4 | 1024 |
| 512 | 4 | 2048 |

```bash
SOURCE_EXPERIMENT=/.../ren_balanced_matched_b256... \
OUTPUT_DIR=/.../rq3_scaling \
bash Lulu/runs/run_rq3_scaling.sh
```

Set `INCLUDE_VANILLA=1` to run the same scaling matrix for Vanilla OPD as well.
Every round checkpoint is retained; all intermediate checkpoints are evaluated
on the frozen dev set, while every Round4 model is evaluated on the external
suite.

`summarize_rq3_scaling.py` writes:

- `learning_curve.csv`: dev accuracy vs cumulative unique prompts for every
  checkpoint;
- `benchmark_heatmap.csv`: eight final metrics for every budget -- five raw
  benchmarks plus Math Avg., OOD Avg. and external micro accuracy;
- `coverage.csv`: reasoning positions, token-weight ESS/fraction, prompt-loss
  ESS/fraction, top-1/top-10 mass, mean applied weight and both Teacher-KL
  retention ratios;
- `compute_frontier.csv`: Math/OOD/micro performance and deltas together with
  response tokens, causal/hindsight prompt tokens, Teacher/Hindsight scored
  sequence tokens/positions, service time and round wall-clock.

**Storage note.** Retaining every full-parameter round checkpoint for all scaling
arms can be large.  These checkpoints are required only until the planned dev
and fixed-prefix analyses are finished; pruning policy should be decided on the
cluster after those analyses, not inside the scientific controller.

## RQ3.2: inference-budget / reasoning-efficiency analysis

Every paper evaluation stores `response_token_ids`, so the same 32k generations
can be rescored at shorter budgets without any new generation:

```bash
EVALUATION_DIR=/.../evaluation \
OUTPUT_DIR=/.../inference_budget \
bash Lulu/runs/analyze_rq3_inference_budget.sh
```

The default budgets are 2k/4k/8k/16k/32k.  Outputs are:

- `prefix_scores.csv`: per-example prediction/reward, valid-answer flag,
  closed-thinking flag and prefix length at every budget;
- `first_budget.csv`: first tested closed/valid/correct budget per example;
- `budget_summary.csv`: per-model/per-benchmark accuracy and completion metrics;
- `budget_grouped_summary.csv`: Math Avg., OOD Avg., external macro/micro by
  inference budget;
- `solve_by_budget.csv`: cumulative fraction with a valid/correct/closed answer
  by each tested budget.

This is a same-trajectory prefix audit, not an independent resampling at each
budget.

## Persisted training telemetry

Every `ren_balanced` round now saves both the intrinsic bounded ReN score and
the weight actually applied by the experimental arm:

- `diagnostics/round_xxxx/position_scores.npz`: `D_C`, `D_H`, signed resolved
  mismatch, raw/bounded ReN, `applied_weight`, OPSD causal KL, trajectory index,
  absolute response position;
- `diagnostics/round_xxxx/trajectory_scores.jsonl`: source ID, response/reasoning
  lengths, cap flag, base/applied weight mass, raw/applied Teacher KL sums,
  prompt/rollout scales and allocation invariants;
- `diagnostics/round_xxxx/summary.json`: 2k position bins, positive fraction,
  weight quantiles/concentration, token ESS, prompt-loss ESS, prompt top-10 loss
  share, and **both** token-global and actual prompt-balanced retained Teacher-KL
  fractions;
- `metrics/round_xxxx.json`: response tokens, causal/hindsight prompt tokens,
  Teacher/Hindsight scored sequence tokens and positions, service time, update
  time, total round time, component losses/gradients and stability information.

Together with retained checkpoints and stored evaluation token IDs, these files
cover the planned RQ2/RQ3 plots without rerunning the 32B Teacher.  The only
planned post-hoc GPU task is optional fixed-prefix Student policy drift, which
loads Student checkpoints but performs no generation.

## Cheap task tests

Run:

```bash
bash Lulu/runs/smoke_rq_tasks.sh
```

The smoke suite is CPU-only and does not load a real LLM.  It checks:

- ReN/Uniform/Shuffled/Causal allocation invariants;
- RQ1, RQ2.1/2.2, RQ2.3 and RQ3.1 experiment planners;
- RQ1/RQ2/RQ3 table summarizers;
- RQ2 geometry extraction and round-safe trajectory grouping;
- fixed-prefix policy-drift command construction/sampling;
- inference-budget prefix rescoring;
- `--help` startup for every new RQ runner/analyzer/summarizer.

The full model-integration suite still requires the project's actual environment
(`transformers`, tokenizer/math-parser dependencies, and GPUs); the cheap suite
is intended only to catch experiment-plan and analysis regressions before a
costly run.
