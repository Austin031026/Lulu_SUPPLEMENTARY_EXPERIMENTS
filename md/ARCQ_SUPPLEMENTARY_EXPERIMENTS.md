# ArcQ 补充实验

## 原始补充实验要求

### 实验1：

**这个实验要检验的是：hindsight 分数能否提前识别出，学生经过训练后更容易吸收的教师监督。**

这里的“吸收”需要具体定义：**学生在不提供答案的情况下，对教师分布的拟合是否改善。** 最终答题准确率是另一个层面的结果，这个实验主要验证文章中 learnability 的含义。

#### 1. 现在的 hindsight 分数测量了什么？

固定学生参数、题目和已经生成的推理前缀，比较两种情况：

- 学生没有看到答案；
- 同一个学生额外看到了正确答案。

你们的分数是：

# \[ S\_t

## \underbrace{D\_{\mathrm{KL}}(q\_T\|p\_0)}\_{\text{不给答案时的差距}}

\underbrace{D\_{\mathrm{KL}}(q\_T\|p\_0^H)}\_{\text{提供答案后的差距}}.\
\]

分数高意味着：

> 只要补充正确答案，同一个学生就会更支持教师在这个位置上的判断。

这个计算过程中，**学生参数没有更新**。因此，它直接测量的是学生对额外信息的反应。

接下来要验证的推断是：

> 这种对额外信息的反应，能否预测学生之后通过参数更新获得的改善？

这就是新实验要补上的联系。

#### 2. 具体怎么做？

**第一步：固定一批诊断题目和推理前缀**

从已有数学数据中留出一批**不参与这次训练**的题目，不需要构造新 benchmark。

用训练前的学生，在没有答案的情况下生成推理轨迹。保存这些轨迹，之后始终在相同的前缀上比较模型。

对于每个推理位置，计算：

- 教师分布；
- 学生的 causal 分布；
- 学生看到正确答案后的 hindsight 分布；
- 初始 causal KL；
- hindsight 分数。

**这些分数只用于分析，不参与后续训练。**

**第二步：执行一个共同的训练过程**

在另一批训练题目上，使用普通 OPD 训练学生。保留既定训练配置，推理监督不使用 HinD 权重。

这里“统一训练”的意思是：

> 所有诊断位置都通过同一对训练前、训练后的模型来评价；不根据它们的 hindsight 分数安排不同的训练。

这样可以避免一个循环解释：高分位置因为被 HinD 赋予更多权重，所以后来改善更多。

**如果已经保存了 OPD 的中间 checkpoint，这一步可以直接复用。** 可以先选一个预先确定的训练区间，例如某个 checkpoint 到之后若干步；具体取决于现有 checkpoint，不必重新跑完整实验。

**第三步：训练后重新评估完全相同的前缀**

用更新后的学生，重新读取第一步保存的题目和推理前缀。**不给正确答案，也不重新生成另一条轨迹。**

重新生成会改变推理状态，无法判断变化究竟来自参数更新，还是因为模型走到了另一条路径。

设更新后的 causal 分布为：

\[\
p\_1.\
\]

实际改善定义为：

# \[ G\_t

## D\_{\mathrm{KL}}(q\_T\|p\_0)

D\_{\mathrm{KL}}(q\_T\|p\_1).\
\]

它的含义很直接：

- 正值：训练后，学生更接近教师；
- 零附近：基本没有变化；
- 负值：训练后反而离教师更远。

这一次，改变的是**模型参数**，学生没有获得额外答案信息。

**第四步：比较“事前分数”和“事后改善”**

我们希望检验：

> 在初始条件相近的位置上，训练前 hindsight 分数较高的位置，训练后是否具有更大的 causal 改善？

例如，下面只是说明计算方式，**不是实际结果**：

| 位置初始 causal KL提供答案后的 KLHindsight 分数训练后的 causal KL实际改善 |      |      |      |      |      |
| ----------------------------------------------------- | ---- | ---- | ---- | ---- | ---- |
| A                                                     | 0.80 | 0.30 | 0.50 | 0.50 | 0.30 |
| B                                                     | 0.80 | 0.77 | 0.03 | 0.76 | 0.04 |

如果这种关系在大量题目上稳定出现，就说明：

> hindsight 所揭示的兼容性，确实包含了关于后续学习效果的预测信息。

#### 3. 最关键的控制：初始 causal KL 必须相近

**不能直接把所有 token 的 hindsight 分数与 KL 下降画一张相关性图，然后就下结论。**

因为这两个量都包含初始 causal KL：

\[\
S\_t=D\_{0,t}-D^H\_{0,t},\
\qquad\
G\_t=D\_{0,t}-D\_{1,t}.\
\]

初始差距较大的位置，本来就可能有更多下降空间。直接相关可能只是反映这一点。

一个容易解释的做法是：

1. 先按照初始 causal KL，把位置分成若干组；
2. 在每组内部，再按 hindsight 分数分成低、中、高几档；
3. 比较各档训练后的平均改善；
4. 汇总不同初始 KL 组的结果。

这样回答的问题才是：

> **当教师与学生原本的分歧相近时，hindsight 能否进一步区分哪些监督更容易被吸收？**

统计时还应按题目或轨迹计算不确定性，避免把同一条轨迹上的几千个 token 当作几千个独立样本。

#### 4. 最后应该展示什么？

我建议主结果只用一张图：

- \*横轴：\*\*控制初始 causal KL 后的 hindsight 分数分组；
- \*纵轴：\*\*训练后的平均 causal KL 改善；
- \*误差条：\*\*按题目重采样得到的不确定性。

理想的现象是：从低分组到高分组，实际改善总体增加。不需要每一档都严格单调，但趋势应当稳定。

需要留意：你们实际的权重会截断负分数，因此也值得把**非正分数的位置单独展示**，看看被 gate 排除的监督是否确实较少受益。

#### 5. 这个实验能支持到什么程度？

如果结果成立，它会补上当前论证中很有价值的一环：

> **同一个学生在额外信息下表现出的兼容性，能够预测它在无答案条件下通过训练获得的拟合改善。**

但结论需要限定在所测试的学生、教师、训练方式和预算内。教师分布本身也可能有错误，因此“更接近教师”并不自动等于“最终解题正确率提高”。

你们现有的两类实验可以形成互补：

| 实验回答的问题       |                              |
| ------------- | ---------------------------- |
| 这个预测实验        | Hindsight 分数是否包含关于后续学习效果的信息？ |
| Table 3 的匹配消融 | 根据这个分数分配监督，是否真的改善最终任务表现？     |

**所以，我建议把它定位成一项机制验证。最经济的起步方式，是利用已有 OPD checkpoint，在一批留出题目的固定前缀上完成分析；先确认是否存在可信的预测关系，再决定是否扩展。**

### 实验2：

#### 给 Table 3 增加一个 Low-KL-Matched / Entropt-Matched 对照

建议增加两个对照：

| 对照分配规则回答的问题         |                                 |                  |
| ------------------- | ------------------------------- | ---------------- |
| **Low-KL-Matched**  | 将较大权重分配给 causal KL 较小的位置        | 是否主要来自“先学容易的”？   |
| **Entropy-Matched** | 将较大权重分配给学生 causal entropy 较高的位置 | 是否主要来自“优先学不确定的”？ |

两者都沿用现有 matched-control 设计：保持每条轨迹的权重集合、总量和稀疏性，改变分配位置。

已有工作 TIP 就研究了学生熵与教师—学生分歧如何共同决定 token 重要性，因此 entropy 对照具有明确的文献依据。[arxiv.org](https://arxiv.org/html/2604.14084v2?utm_source=chatgpt.com)

**建议先在 Qwen3-1.7B ← Qwen3-32B 上完成，沿用投稿配置和评测协议。**

需要注意：这些对照仍然借用了 HinD 的权重集合，因此回答的是**分配规则的价值**；它们不能被称作完全不需要 hindsight 的替代算法。

### 实验3：

#### 同步记录计算成本

**可能的质疑：**

> HinD 多了一次 hindsight 前向，收益是否值得这些开销？

至少整理同一硬件环境下 HinD、OPD、OPSD 的：

- 总 GPU-hours；
- rollout 和训练更新分别耗时；
- 实际生成 token 数；
- 峰值显存；
- 对应的最终准确率。

现有日志足够时直接整理；缺少记录的部分，可以在新增运行中补测。
